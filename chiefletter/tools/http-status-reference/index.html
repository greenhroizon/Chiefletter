Use cases

  • Add a clear status explanation to an API bug report.
  • Review which client responses are normally retryable or require user action.

Notes and limits

The reference covers common codes and general HTTP meaning. An API may use a code in a service-specific way within protocol rules. Do not retry every failure automatically. Consider request idempotency, retry limits, backoff, and the service’s documented guidance.

Frequently asked questions

What are the HTTP status code classes?

1xx is informational, 2xx indicates success, 3xx indicates redirection, 4xx describes a client-side request issue, and 5xx describes a server-side failure.

Should a client retry a 4xx response?

Usually not without changing the request or addressing the cause. A 429 response may include retry guidance. Follow the API contract.

Does 200 always mean the requested work is complete?

It means the request succeeded according to the response. Some operations return 202 to indicate accepted work that continues asynchronously.

Why might an API return 404 instead of 403?

Some services conceal whether a protected resource exists. Follow that API’s security and error-handling contract.

JWT decoder

Read a token header and payload locally.

Decode the header and payload portions of a JSON Web Token in the browser. The page does not send the token anywhere and does not verify its signature. A decoded claim is only readable data, not proof that the token is genuine or current.

JWT decoder

Runs in your browser. Your input is not sent to Chiefletter.

How to use this tool

  1. Paste the three-part token into the field.
  2. Run the decoder to inspect the JSON header and payload.
  3. Check issuer, audience, and expiry against the service that issued the token. Never use decoded data as authorization evidence.

Use cases

  • Inspect a test token while debugging local authentication.
  • Read an expiration timestamp from a development token.
  • Check claim names before updating client integration code.

Notes and limits

Do not paste a live production token into a shared device. Anyone who obtains a valid bearer token might use it until it expires or is revoked. This page does not validate the signature.

Frequently asked questions

Does decoding verify the JWT signature?

No. It only decodes the first two Base64URL sections. Use the issuer’s key and a trusted JWT library to verify a signature.

Is the token sent to a server?

No. Decoding happens locally in this browser page. Still avoid sharing live credentials on a shared computer.

What does an expired claim mean?

The page compares the exp value with the device clock. The service remains authoritative about whether it accepts the token.

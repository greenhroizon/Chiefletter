Git and version control for beginners

Version control tracks changes to your files and makes teamwork possible. Learn the core ideas behind Git.

Why version control

Version control records every change to a project so you can see what changed, who changed it and why, and go back if something breaks. It also lets several people work on the same files without overwriting each other.

Key concepts

  • Repository: the project and its history.
  • Commit: a saved snapshot with a message describing the change.
  • Branch: a separate line of work that can be merged back.
  • Remote: a copy hosted online for backup and collaboration.

A simple workflow

Create a branch for each task, make small commits with clear messages, push to the remote and open a review request so teammates can comment before merging. Pull the latest changes often to avoid large conflicts.

Avoid common mistakes

Never commit passwords or API keys, because history keeps them even after deletion. Use a file that lists items to ignore, and commit often in small pieces.

Your first Git session

Create a folder for a small project and initialize a repository. Add a file, check the status, stage the file and commit with a clear message such as 'Add project readme'. Make another change, view the differences and commit again. You now have a history you can browse.

Next, create a branch, make a change, and switch back to see that the main branch is unchanged. Merge the branch when you are happy with it. Finally, create an online repository, add it as a remote and push your work. If a merge conflict appears, open the file, choose which lines to keep and commit the result. Practicing on a throwaway project builds confidence before you work on anything important.

Frequently asked questions

Is Git the same as GitHub?

No. Git is the tool; GitHub is a service that hosts Git repositories.

What is a merge conflict?

When two changes touch the same lines and need a human decision.

How often should I commit?

Whenever you complete a small, logical change.

Can I undo a commit?

Yes, with commands that revert or reset, but ask for help before rewriting shared history.

Key terms

Repository
A project and its history.
Branch
A parallel line of development.
Pull request
A proposal to merge changes.
The bottom line. Version control gives you a safety net and a shared history. Learn the basics and use them daily.
